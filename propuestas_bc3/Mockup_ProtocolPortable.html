Com funciona la portabilitat

  • El Protocol és un conjunt de regles, no de IDs. Cada regla diu "si es compleix X, l'element pertany a Y". X pot ser: nom de Workset, patró/regex de nom, keyword, rang d'elevació, parámetre custom, o llista manual com a últim recurs.
  • Auto-detecció en obrir un projecte nou: l'app aplica les regles del Protocol a tot el .rvt actual. Per cada Level i GroupType comprova quina regla matchea i l'assigna a la categoria. El Diagnòstic en viu mostra el resultat: match exacte, match aproximat, no classificat.
  • Si una regla no matchea res (típic en projecte amb nomenclatura diferent): la app destaca els elements sense classificar al panell de Diagnòstic. L'usuari afegeix una regla nova ("els meus levels comencen per BlocA_" → afegeix patró ^BlocA_*) i tot queda classificat.
  • Export/Import.e3gprot: el Protocol es desa com JSON portable. Un estudi pot tenir un protocol "ResidencialEstandard.e3gprot" amb les seves regles habituals i un altre "Industrial.e3gprot". En projecte nou: import → l'app intenta aplicar — si totes les regles matchean, cero clics; si alguna no, l'usuari completa.
  • Estructura jerárquica: Edifici (1) → Interior vivendes / Zones comunes (2) → dins de Zones comunes: Bajantes / Colectores / Aparcamiento (3). Cada pipe acaba en una fulla d'aquesta jerarquia. El Diagnòstic la mostra en arbre.

  "nom": "E3G_Vivendes_2026",
  "edificis": [
    { "id": "A", "nom": "Edifici A", "regles": [
      { "tipus": "workset", "patro": "EDIF_A_*" },
      { "tipus": "levelSuffix", "valor": ".A" }
    ] },
    { "id": "B", "nom": "Edifici B", "regles": [...] }
  ],
  "vivendes": {
    "regles": [
      { "tipus": "groupKeyword", "paraules": ["VIV", "VIVENDA", "HABITATGE"] },
      { "tipus": "groupRegex", "patro": "^M_(?:Vivenda|Apartament)_T\\d+$" }
    ]
  },
  "bajantes": {
    "geometria": { "verticalQuant": "dz_gt_dxy", "longitudMinM": 1.0 },
    "toleranciaM": 0.5
  },
  "colectores": {
    "nivellInferior": { "tipus": "levelPattern", "valor": "P00.*" },
    "nivellSuperior": { "tipus": "levelPattern", "valor": "P01.*" },
    "toleranciaM": 0.5
  },
  "aparcamiento": {
    "regles": [
      { "tipus": "levelRegex", "patro": "^S\\d+\\.[AB]$" },

  }

Plan d'implementació realista (per a quan vulguis arrencar-lo)

  • Fase 1 — Modelo de Protocol (~3h): classes Protocol, ReglaDeteccio (interfície + implementacions: ReglaWorkset, ReglaPatroNom, ReglaRegex, ReglaKeyword, ReglaElevacio). Tests unitaris contra noms d'exemple.
  • Fase 2 — Persistència i export (~2h): JSON serialization polimòrfica (mateix patró que SubFiltroJsonConverter). Export/Import del .e3gprot com fitxer.
  • Fase 3 — Auto-detecció (~3h): donat un Document Revit, generar un Protocol inicial mirant els Levels, GroupTypes i Worksets reals. Heurístiques per pre-marcar el què cuadra.
  • Fase 4 — UI (~5h): la pantalla d'aquest mockup. 5 sections + diagnòstic en viu. Recompute del diagnòstic en cada canvi.
  • Fase 5 — Integració amb AgrupadorMediciones (~2h): el helper actual passa a llegir el Protocol guardat (caché en memòria) en lloc de tenir criteris hardcoded.
  • Total: ~15h de desenvolupament + testing. La caché de protocol per sessió és un patró ja validat (PartidasSession, ClasificacionSession).
