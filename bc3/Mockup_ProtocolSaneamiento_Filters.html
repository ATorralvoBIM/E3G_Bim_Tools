Per què el patró "filter style" funciona realment

  • Reusa el paradigma de Revit: és exactament el formulari de "Selection Filter" / "View Filter" de Revit. L'usuari ja sap utilitzar-lo, no aprèn cap concepte nou.
  • Funciona en qualsevol projecte: els paràmetres (Workset, Reference Level, Name, Mark, paràmetres compartits...) existeixen a tots els .rvt. La regla s'avalua contra el .rvt actual i punt.
  • Implementació directa amb la API de Revit: ParameterFilterUtilities.GetFilterableParameters(doc, categoryId) dóna la llista de paràmetres filtrables per categoria — el que omple el dropdown. FilterStringContains, FilterStringBeginsWith, FilterDoubleRule... avaluen els operadors. Tot és built-in a la API.
  • Multi-condició AND/OR: cada regla pot tenir N condicions. L'usuari tria si "totes" (AND) o "qualsevol" (OR) — equivalent als grups de filtres de Revit.
  • Preview en viu: el formulari mostra mentre escrius quants elements del projecte actual matchejaria la regla. Això és el que falta a Revit i el que farà la UI nostra millor.
  • Casos especials geomètrics (Bajantes "vertical", Colectores "horitzontal"): són paràmetres pseudo-virtuals que el helper calcula al moment. A la UI els mostrem com qualsevol altre paràmetre amb operador "VERTICAL"/"HORIZONTAL" — l'usuari els tria del mateix dropdown.

Llista de paràmetres que apareixen al desplegable (per a Sanejament)

  • Per Pipes: Workset, Reference Level (nom i elevació), Length, Diameter, System Name, System Type, Mark, Comments, més qualsevol Shared Parameter del projecte.
  • Per Group Types: Type Name, Type Mark, Type Comments, més qualsevol Type Shared Parameter.
  • Per Levels: Name, Elevation, més paràmetres custom.
  • Geometria pseudo-paràmetre (només Bajantes/Colectores): Orientació (Vertical / Horizontal), Length, Centre Z.

Estimació realista d'implementació

  • Modelo (~3h): FilterCondition (param + operator + value), Regla (name + conditions[] + AND/OR), Protocol (regles per secció).
  • Avaluador (~3h): donat un Element + Regla, retorna true/false. Llegeix paràmetres via Element.LookupParameter o Element.get_Parameter(BuiltInParameter). Aplica operador. Combina amb AND/OR.
  • UI del formulari (~5h): dropdown de paràmetres (carregat amb GetFilterableParameters), dropdown d'operadors (depèn del tipus del paràmetre — string vs number), input del valor, +Afegir condició, AND/OR toggle, preview en viu.
  • UI principal (~3h): les 5 sections amb llista de regles, expansió/col·lapse, add/edit/delete.
  • Persistència JSON + Import/Export .e3gprot (~2h): serialització polimòrfica.
  • Auto-detect inicial (~2h): genera regles per defecte mirant el .rvt actual (Worksets típics, Levels per S/P, Group Types amb keywords típiques).
  • Integració amb AgrupadorMediciones (~2h): el helper passa a llegir el Protocol; cada pipe s'avalua contra les regles per arribar al seu grup.
  • Total: ~20h. Una mica més que el plan abstracte anterior pero molt més fiable. El cost extra es paga sol al primer projecte nou que obrim sense problemes.
